# Cache explicado para iniciantes

## O que é cache?

**Cache** é uma cópia guardada de uma informação para que você não precise buscá-la de novo toda vez que ela for necessária.

Buscar dados numa API costuma ser **lento** (a requisição viaja pela internet), **custoso** (algumas APIs cobram por chamada ou limitam a quantidade) e **pesado** para o servidor que responde. Por isso, em vez de perguntar sempre, o programa guarda a resposta por um tempo e a reutiliza.

## O exemplo: preço com validade de 30 segundos

Imagine uma página que mostra o preço de um produto vindo de uma API. Ela segue esta regra:

1. Quando alguém pede o preço, a página verifica se já tem um valor guardado.
2. Se o valor tem **menos de 30 segundos**, ela usa esse valor e não chama a API.
3. Se tem **30 segundos ou mais** (ou se não há valor guardado), ela consulta a API, guarda o novo preço e anota a hora.

Esse prazo de validade se chama **TTL** (*Time To Live*, "tempo de vida").

Em código (JavaScript), a ideia fica assim:

```javascript
let precoGuardado = null;
let horaQueGuardou = 0;
const VALIDADE_MS = 30_000; // 30 segundos

async function obterPreco() {
  const agora = Date.now();
  const aindaValido = precoGuardado !== null && (agora - horaQueGuardou) < VALIDADE_MS;

  if (aindaValido) {
    return precoGuardado;          // usa o valor guardado (rápido)
  }

  const resposta = await fetch("https://api.exemplo.com/preco");
  const dados = await resposta.json();
  precoGuardado = dados.preco;     // guarda o novo valor
  horaQueGuardou = agora;          // anota quando guardou
  return precoGuardado;
}
```

## Um detalhe importante: ninguém avisa o cache

Esse cache **não recebe notificações** quando o preço muda. Ele não sabe o que acontece na API. Só descobre um preço novo quando o prazo acaba e uma nova consulta é feita.

Veja uma linha do tempo:

| Hora | O que acontece | Preço na API | Preço mostrado |
|---|---|---|---|
| 10:00:00 | Página consulta a API e guarda o valor | R$ 10 | R$ 10 |
| 10:00:12 | O preço muda na API | **R$ 12** | R$ 10 |
| 10:00:20 | Alguém pede o preço; o cache ainda vale | R$ 12 | **R$ 10** (desatualizado) |
| 10:00:31 | Alguém pede o preço; o prazo venceu e a página consulta a API | R$ 12 | R$ 12 |

Entre 10:00:12 e 10:00:31, a página mostrou um preço que **já não era o real**. Um dado assim é chamado de **dado obsoleto** (*stale*, em inglês). Pela regra dos 30 segundos, o valor guardado nunca passa desse tempo sem ser renovado. Se ninguém pedir o preço depois do vencimento, a nova consulta só acontece no próximo pedido.

## A comparação cotidiana: o preço do pão anotado no papel

Imagine que você trabalha no caixa de uma lanchonete e, para saber o preço do pão, precisa ir até a padaria do outro lado da rua e perguntar ao padeiro.

Para não atravessar a rua a cada cliente, você combina consigo mesmo: *"Vou anotar o preço num papelzinho com o horário. Durante 30 segundos, confio no papel. Depois disso, volto para perguntar."*

**A vantagem:** se chegarem 20 clientes em 30 segundos, você atravessa a rua **uma vez só**, e não vinte. O atendimento fica muito mais rápido, você se cansa menos e o padeiro não é interrompido o tempo todo. Na página, isso significa resposta mais rápida, menos chamadas à API e menos carga no servidor.

**O risco:** o padeiro **não vai atravessar a rua para avisar** que mudou o preço. Se ele reajustar o pão 10 segundos depois da sua anotação, você vai cobrar o valor antigo dos próximos clientes até o papel vencer. Na página, isso significa mostrar por alguns segundos um preço que não vale mais.

## Resumindo

- **Cache** guarda uma resposta para reutilizá-la sem buscar de novo.
- **TTL** é o prazo durante o qual essa resposta é considerada válida.
- **Vantagem:** velocidade e economia de chamadas à API.
- **Risco:** como o cache não é avisado das mudanças, ele pode mostrar um valor desatualizado até o prazo vencer.

A escolha do prazo é um equilíbrio. Um prazo **maior** dá mais economia, mas o dado pode ficar desatualizado por mais tempo. Um prazo **menor** mantém o dado mais fresco, mas gera mais consultas. Para o preço de um produto numa vitrine, 30 segundos de atraso costuma ser aceitável. Para a cotação de ações numa corretora, talvez não seja.
