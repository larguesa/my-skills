O bug está no argumento padrão `bucket=[]`: essa lista é criada uma única vez, quando o Python executa a definição da função, e é reutilizada nas chamadas que omitem `bucket`. Para criar uma lista por chamada sem substituir uma lista fornecida pelo chamador, use `None` como padrão:

```python
def collect(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

### Por que a versão original acumula itens

`append` altera a própria lista. Na versão original, `collect("A")` acrescenta `"A"` à lista padrão; depois, `collect("B")` acrescenta `"B"` à mesma lista. Por isso, a segunda chamada retorna `["A", "B"]`. A lista retornada pela primeira chamada também passa a conter os dois itens.

Na correção:

- Se `bucket` for omitido ou receber `None`, a função cria uma lista.
- Se o chamador fornecer uma lista, mesmo vazia, a função acrescenta o item a ela e retorna o mesmo objeto.

Não use `if not bucket` nem `bucket = bucket or []`: essas alternativas substituiriam uma lista vazia fornecida pelo chamador.

### Testes

Execute estes testes após a definição corrigida:

```python
# Chamadas sem bucket usam listas independentes.
first = collect("A")
second = collect("B")

assert first == ["A"]
assert second == ["B"]
assert first is not second

# Uma lista vazia fornecida pelo chamador mantém sua identidade.
bucket = []
result = collect("A", bucket)

assert result is bucket
assert bucket == ["A"]

# Chamadas seguintes continuam alterando essa mesma lista.
result = collect("B", bucket)

assert result is bucket
assert bucket == ["A", "B"]

# Itens existentes são preservados.
existing = ["X"]
result = collect("Y", existing)

assert result is existing
assert existing == ["X", "Y"]

# O uso de uma lista explícita não interfere nas chamadas sem bucket.
assert collect("C") == ["C"]
```

Os testes passam sem produzir saída. `==` verifica o conteúdo; `is` verifica se o retorno é exatamente a lista fornecida.
