## O bug

O valor padrão `bucket=[]` é avaliado uma única vez, quando o Python executa a instrução `def`, e não a cada chamada. A lista criada nesse momento fica guardada no objeto da função (em `collect.__defaults__`) e é reutilizada por todas as chamadas que omitem `bucket`.

Por isso, em um processo novo:

```python
>>> collect("A")
['A']
>>> collect("B")
['A', 'B']
>>> collect.__defaults__
(['A', 'B'],)
```

A segunda chamada não recebe uma lista vazia. Ela recebe a mesma lista em que a primeira já tinha acrescentado `"A"`. O estado persiste até o processo terminar, e cada chamada sem `bucket` passa a depender das anteriores.

## A correção

Use `None` como valor padrão e crie a lista dentro da função:

```python
def collect(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

O comportamento fica assim:

| Chamada | Efeito |
|---|---|
| `collect(item)` | Cria uma lista nova, acrescenta `item` e a retorna. |
| `collect(item, lista)` | Acrescenta `item` a `lista`, o mesmo objeto passado pelo chamador, e retorna `lista`. |
| `collect(item, [])` | Acrescenta `item` à lista vazia passada e retorna esse mesmo objeto. |

### Caso de borda: não use `bucket or []`

A forma abreviada abaixo parece equivalente, mas quebra o contrato:

```python
def collect(item, bucket=None):
    bucket = bucket or []   # errado
    bucket.append(item)
    return bucket
```

Uma lista vazia é falsa em contexto booleano. Se o chamador passar `[]`, a função descarta essa lista, cria outra e acrescenta o item nela. O chamador fica com a lista original ainda vazia. O teste `if bucket is None` só substitui o argumento quando ele foi de fato omitido (ou quando o chamador passou `None` explicitamente).

## Testes

Os testes abaixo usam `pytest`. Salve-os em `test_collect.py` junto do módulo que define `collect` e execute `pytest test_collect.py`.

```python
from collect import collect


def test_chamadas_sem_bucket_nao_compartilham_estado():
    assert collect("A") == ["A"]
    assert collect("B") == ["B"]


def test_chamadas_sem_bucket_retornam_listas_distintas():
    primeira = collect("A")
    segunda = collect("B")
    assert primeira is not segunda


def test_bucket_passado_recebe_o_item_e_e_retornado():
    lista = ["x"]
    resultado = collect("y", lista)
    assert resultado is lista
    assert lista == ["x", "y"]


def test_bucket_vazio_passado_e_o_mesmo_objeto_retornado():
    lista = []
    resultado = collect("A", lista)
    assert resultado is lista
    assert lista == ["A"]


def test_chamadas_sucessivas_acumulam_no_bucket_do_chamador():
    lista = []
    collect("A", lista)
    collect("B", lista)
    assert lista == ["A", "B"]


def test_valor_padrao_permanece_none():
    collect("A")
    assert collect.__defaults__ == (None,)
```

Com a versão original, `test_chamadas_sem_bucket_nao_compartilham_estado` falha na segunda asserção, porque `collect("B")` retorna `["A", "B"]`. Com a versão `bucket or []`, `test_bucket_vazio_passado_e_o_mesmo_objeto_retornado` falha, porque `resultado is lista` é falso e `lista` continua vazia. Com a correção proposta, todos os testes passam.
