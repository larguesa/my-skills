# Criar tarefa

`POST /v1/jobs` cria uma tarefa e a coloca na fila de execução. Use este endpoint para registrar uma nova tarefa, como um backup, identificada por um nome.

## Exemplo

```bash
curl -X POST https://api.example.com/v1/jobs \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"name":"backup"}'
```

Resposta de sucesso:

```http
HTTP/1.1 201 Created
Content-Type: application/json

{"id":"job_123","status":"queued"}
```

O status `queued` indica que a tarefa entrou na fila. Guarde o valor de `id` para identificar a tarefa.

## Requisição

**URL:** `https://api.example.com/v1/jobs`
**Método:** `POST`

### Cabeçalhos

| Cabeçalho | Obrigatório | Valor | Efeito |
|---|---|---|---|
| `Authorization` | Sim | `Bearer <TOKEN>` | Autentica a requisição. Sem ele, ou com token inválido, a API retorna 401. |
| `Content-Type` | Sim | `application/json` | Indica que o corpo está em JSON. |
| `Idempotency-Key` | Não | Chave escolhida por quem chama | Evita criar tarefas duplicadas ao repetir a mesma requisição. Veja [Idempotência](#idempotência). |

### Corpo

| Campo | Tipo | Obrigatório | Restrições |
|---|---|---|---|
| `name` | string | Sim | Não pode ser vazia; até 80 caracteres. |

Um `name` ausente, vazio ou com mais de 80 caracteres faz a API retornar 400.

## Idempotência

Envie o cabeçalho `Idempotency-Key` para repetir uma requisição com segurança, por exemplo, depois de uma falha de rede.

```bash
curl -X POST https://api.example.com/v1/jobs \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: <CHAVE>" \
  -d '{"name":"backup"}'
```

A chave vale por 24 horas. Nesse período:

| Nova requisição | Resultado |
|---|---|
| Mesma chave e mesmo corpo | A API retorna a tarefa já criada, sem criar outra. |
| Mesma chave e corpo diferente | A API retorna 409. |

Esta documentação não define o código HTTP da resposta que devolve a tarefa existente.

## Erros

| Código | Causa | O que fazer |
|---|---|---|
| 400 | `name` inválido: ausente, vazio ou com mais de 80 caracteres. | Corrija o campo `name` e envie de novo. |
| 401 | Token ausente ou inválido. | Envie `Authorization: Bearer <TOKEN>` com um token válido. |
| 409 | `Idempotency-Key` já usada, nas últimas 24 horas, com um corpo diferente. | Use outra chave ou repita o corpo original. |
| 429 | Mais de 60 requisições por minuto com o mesmo token. | Aguarde o número de segundos indicado no cabeçalho `Retry-After` antes de tentar de novo. |

## Limite de requisições

Cada token pode fazer até 60 requisições por minuto. Acima disso, a API responde 429 e informa no cabeçalho `Retry-After` quantos segundos esperar.

## Como verificar o resultado

A tarefa foi criada quando a resposta tem código 201 e o corpo traz um `id` e `status` igual a `queued`. Qualquer outro código indica que a requisição falhou. Consulte a tabela de erros para identificar a causa.
