# Criar tarefa

Use POST https://api.example.com/v1/jobs para criar uma tarefa. No sucesso, a tarefa entra na fila.

```bash
curl -X POST "https://api.example.com/v1/jobs" \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"name":"backup"}'
```

A resposta de sucesso é HTTP 201:

```json
{"id":"job_123","status":"queued"}
```

queued indica que a tarefa entrou na fila. Confira HTTP 201, o campo id e o valor queued em status.

## Corpo

O corpo é JSON, com Content-Type: application/json.

| Campo | Tipo | Obrigatório | Efeito |
| --- | --- | --- | --- |
| name | string | sim | Não vazia, com até 80 caracteres. name inválido, inclusive vazio ou com mais de 80 caracteres, responde HTTP 400. |

## Cabeçalhos

| Cabeçalho | Obrigatório | Efeito |
| --- | --- | --- |
| Authorization | sim | Bearer <TOKEN>. Token ausente ou inválido responde HTTP 401. |
| Idempotency-Key | não | Por 24 horas, a mesma chave e o mesmo corpo retornam a tarefa existente. A mesma chave com corpo diferente retorna HTTP 409. |

## Erros e limite

| HTTP | Condição |
| --- | --- |
| 400 | name inválido. |
| 401 | Token ausente ou inválido. |
| 409 | Mesma Idempotency-Key com corpo diferente, no prazo de 24 horas. |
| 429 | O token superou 60 requisições por minuto. A resposta inclui Retry-After em segundos. |

Em HTTP 429, espere os segundos indicados em Retry-After antes de enviar outra requisição com o mesmo token.
