# Criar uma tarefa

Use `POST https://api.example.com/v1/jobs` para criar uma tarefa e colocá-la na fila. A requisição exige um token Bearer e um corpo JSON com o nome da tarefa.

## Exemplo de requisição

Substitua `<TOKEN>` pelo token de autenticação.

```bash
curl -X POST 'https://api.example.com/v1/jobs' \
  -H 'Authorization: Bearer <TOKEN>' \
  -H 'Content-Type: application/json' \
  -d '{"name":"backup"}'
```

## Cabeçalhos

| Cabeçalho | Obrigatório | Valor e efeito |
|---|---|---|
| `Authorization` | Sim | `Bearer <TOKEN>`. Autentica a requisição. |
| `Content-Type` | Sim | `application/json`. Indica o formato do corpo. |
| `Idempotency-Key` | Não | Chave para repetir a requisição sem criar outra tarefa, nas condições descritas abaixo. |

## Corpo da requisição

```json
{"name":"backup"}
```

| Campo | Tipo | Obrigatório | Restrições |
|---|---|---|---|
| `name` | string | Sim | Não pode ser vazio e deve ter até 80 caracteres. |

## Resposta de sucesso

A API retorna **HTTP 201** com o corpo:

```json
{"id":"job_123","status":"queued"}
```

O campo `id` identifica a tarefa. O status `queued` confirma que ela entrou na fila, não que sua execução terminou.

## Idempotência

Para usar idempotência, envie o cabeçalho `Idempotency-Key`. Durante 24 horas:

- A mesma chave com o mesmo corpo retorna a tarefa existente.
- A mesma chave com um corpo diferente retorna **HTTP 409**.

Ao repetir uma requisição com a mesma chave, mantenha o corpo inalterado para evitar o erro `409`.

## Erros e limite de requisições

| Código HTTP | Condição | Como proceder |
|---|---|---|
| `400` | `name` inválido. | Envie uma string não vazia com até 80 caracteres. |
| `401` | Token ausente ou inválido. | Envie um token válido no cabeçalho `Authorization`, no formato `Bearer <TOKEN>`. |
| `409` | Mesma `Idempotency-Key` com corpo diferente durante o período de 24 horas. | Para recuperar a tarefa existente, repita a requisição com a mesma chave e o mesmo corpo. |
| `429` | Limite de 60 requisições por minuto por token superado. | Aguarde o intervalo informado no cabeçalho `Retry-After`, em segundos, antes de tentar novamente. |
