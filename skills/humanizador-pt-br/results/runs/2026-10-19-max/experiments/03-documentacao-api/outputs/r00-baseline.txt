# API de Tarefas: Criar tarefa

Cria uma nova tarefa e a coloca na fila de processamento.

## Endpoint

```
POST https://api.example.com/v1/jobs
```

## Autenticação

Envie um token Bearer no cabeçalho `Authorization`:

```
Authorization: Bearer <TOKEN>
```

Se o token estiver ausente ou for inválido, a API retorna `401`.

## Cabeçalhos

| Cabeçalho         | Obrigatório | Descrição                                                        |
|-------------------|-------------|------------------------------------------------------------------|
| `Authorization`   | Sim         | `Bearer <TOKEN>`                                                 |
| `Content-Type`    | Sim         | `application/json`                                               |
| `Idempotency-Key` | Não         | Chave para repetir a requisição com segurança. Veja [Idempotência](#idempotência). |

## Corpo da requisição

```json
{
  "name": "backup"
}
```

| Campo  | Tipo   | Obrigatório | Regras                            |
|--------|--------|-------------|-----------------------------------|
| `name` | string | Sim         | Não pode ser vazio. Máximo de 80 caracteres. |

## Exemplo

```bash
curl -X POST https://api.example.com/v1/jobs \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 7f3c9a2e-backup-2024" \
  -d '{"name":"backup"}'
```

O cabeçalho `Idempotency-Key` é opcional e pode ser omitido.

## Resposta de sucesso

**HTTP 201 Created**

```json
{
  "id": "job_123",
  "status": "queued"
}
```

| Campo    | Descrição                                     |
|----------|-----------------------------------------------|
| `id`     | Identificador da tarefa criada.               |
| `status` | `queued` indica que a tarefa entrou na fila. |

## Idempotência

Use `Idempotency-Key` para repetir uma requisição sem criar tarefas duplicadas, por exemplo após uma falha de rede.

As chaves valem por **24 horas**:

- **Mesma chave e mesmo corpo:** a API retorna a tarefa já existente, sem criar outra.
- **Mesma chave e corpo diferente:** a API retorna `409 Conflict`.

Recomenda-se gerar uma chave única (por exemplo, um UUID) para cada operação lógica.

## Limite de requisições

O limite é de **60 requisições por minuto por token**. Ao ultrapassá-lo, a API retorna `429 Too Many Requests` com o cabeçalho `Retry-After`, que informa quantos segundos esperar antes de tentar de novo.

```
HTTP/1.1 429 Too Many Requests
Retry-After: 30
```

## Erros

| Código | Significado           | Causa                                                    |
|--------|-----------------------|----------------------------------------------------------|
| `400`  | Bad Request           | `name` ausente, vazio, com mais de 80 caracteres ou que não é string. |
| `401`  | Unauthorized          | Token ausente ou inválido.                               |
| `409`  | Conflict              | `Idempotency-Key` reutilizada com um corpo diferente em até 24 horas. |
| `429`  | Too Many Requests     | Mais de 60 requisições por minuto com o mesmo token. Consulte `Retry-After`. |
