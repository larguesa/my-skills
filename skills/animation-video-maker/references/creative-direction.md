# Creative direction: four separate decisions

A style describes appearance. A technique describes movement. A recipe describes how a message unfolds. A backend describes how pixels are produced. Do not create a new style for every transition or tool.

## Local selection, no API required

1. Read the [brief](../templates/creative-brief.md). Honor explicit choices unless they conflict with rights, factual accuracy or delivery constraints.
2. Choose the execution route: code for exact diagrams/type/UI; generative footage for organic imagery that can tolerate stochastic motion; hybrid for footage plus exact editorial graphics.
3. Choose a narrative structure by the communication job below.
4. Choose one style from the existing [style selection guide](style-selection.md), or a new guide below.
5. Choose one primary motion device. Before export, ask: would removing it weaken the meaning? If not, simplify.
6. Read only the selected recipe and necessary technique section. Optional Jev ranks public descriptions, not confidential briefs, and never replaces the local decision.

## Communication jobs

| Job | Useful structure | Motion device | Main evidence gate |
|---|---|---|---|
| Show a product task | Intent, real interaction, visible result | UI morph, cursor continuity, camera follow | Actual UI and truthful result |
| Make a phrase memorable | Setup, tension, visual transformation, resolution | Semantic typography, occlusion | Exact approved words and reading time |
| Explore a world or system | Establish scale, pass a threshold, reveal a new scale | Portal, nested zoom, parallax | Honest illustrative versus real environment |
| Explain a relationship | Question, construction, consequence | Progressive drawing, match cut | Causal claim supported by source |
| Build an identity loop | Motif, variation, return | Periodic motion, hidden reset | Continuous boundary position and velocity |
| Launch or announce | Hook, proof, differentiated benefit, action | Measured camera and typographic hierarchy | Verified features, not fake KPIs |
| Tell a musical story | Phrase, development, release | Beat grid with purposeful off-beat holds | Track rights, audible synchronization |

See [recipe library](../recipes/README.md) for executable production briefs. Existing T2S examples remain a teaching gallery, not a mandate to use three phases and an identical end card for every request.

## Additional visual languages

- [Product interface](../styles/product-interface/SKILL.md): controlled spacing, UI hierarchy and continuous interaction. An illustrative interface must be labeled; a real demo uses actual authorized assets.
- [Generative geometry](../styles/generative-geometry/SKILL.md): systems of shapes, recursion, fields and spatial rhythm. Here *generative* means procedural design, not necessarily a text-to-video model.

Combine across layers: paper cutout with a portal; blueprint with a match cut; product interface with a morph loop; kinetic typography with phrase-driven pauses. A recipe need not introduce a new style.

## Production tradeoffs

- An attractive screenshot does not prove that motion is good. Review transitions and playback, not just posters.
- Exporting portrait is not cropping or stretching landscape: recompose focal points, type and controls.
- Motion blur can improve fast moves, but multiplies render work. Use it only after a sharp-frame version is correct.
- A seamless loop requires compatible motion at the wrap point. Do not duplicate the endpoint frame in the export.
- Audio may be optional, but its state must be explicit. Do not make the message depend solely on sound.
- Prefer a short well-resolved sequence to a long showreel that mixes unrelated effects.

## Scope

The code path has local reproducibility checks. Generative and hybrid guidance is a prompt/planning route, not a bundled provider integration or a promise of identical frames. See the selected backend's prerequisites and the [sources register](creative-sources.md) before adding tools or copying assets.
